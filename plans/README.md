## Direction findings (options for the maintainer, not ranked against bugs)

1. **Deliver offchain publish (IPFS / Astral API)** — `publishOffchainLocationAttestation`
is a silent no-op (`src/core/AstralSDK.ts:943-952`, verified) and
`AstralApiClient.publishOffchainProof` throws 501. The PRD names publish as
a core requirement and it's the missing half of the offchain headline use
case. Trade-off: requires picking the storage default (Astral API vs IPFS)
and a publication-record contract. Effort M (coarse).
2. **Finish spatial/temporal querying** — query scaffolding exists
(`AstralApiClient.getLocationAttestations` builds bbox/time params) but the
response mapper is an unchecked cast and the v0.2 surface doesn't expose
querying at all, while the PRD's map/geofence use case depends on it.
Trade-off: needs the live API contract confirmed first. Effort M (coarse).
3. **Ship one real plugin** — the plugin system is fully specified with a
working mock (real ECDSA lifecycle in `src/plugins/mock/`), and the
registry's `mock-` prefix enforcement signals real plugins are expected;
none exist. A browser-Geolocation plugin is one interface implementation
away and would make `stamps.collect()` genuinely useful. Effort M per
plugin (coarse).
4. **Decide the legacy sunset** (finding #13) — every direction above lands
twice as expensively while two SDK surfaces coexist; a deprecation
timeline + migration guide is the cheapest way to stop the bleeding.
